# Harness HC

HC is the user-facing endpoint for Harness Platform. The first implementation is a responsive H5 application under `web/`; reusable identity, secure storage, protocol, and session logic lives under `packages/core/`.

The H5 MVP provides:

- P-256 signing and KEM keys generated by WebCrypto with non-extractable private keys;
- IndexedDB structured-clone persistence checks for `CryptoKey` handles;
- an explicit, non-persistent `web-ephemeral` fallback instead of plaintext key export;
- RFC 7638 public-key thumbprints;
- a fail-closed connection state machine;
- a responsive H5 readiness screen.
- Admin-session-bound HC registration followed by Endpoint DPoP data-plane calls;
- one-time WSS Ticket, signed challenge/READY and pinned Gateway trust;
- Session creation, RFC 9180 Key Package open and end-to-end encrypted ACP Prompt/Response;
- a bounded IndexedDB Inbox, signed ACK, exact encrypted-frame Resume replay and dedupe;
- explicit stale-Session cleanup, CloseTunnel, offline recovery and `UNCERTAIN` UI.

Private Session keys remain in page memory. A full page reload therefore fails closed and
offers to close unrecoverable active Sessions; same-page network reconnect retains keys
and sends signed ResumeState.

## Development

Node 24 and pnpm 10.34.5 are required.

```text
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm dev
```

Private keys, access credentials, refresh credentials, and session keys must never be serialized to JSON or written to Local Storage.
