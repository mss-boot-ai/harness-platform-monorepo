ABA 设备授权（Enrollment）

本机启动 ABA 后，用户在一个已认证的 HC 上批准该设备，Platform 才下发用该 ABA KEM 公钥保护的凭据。原型覆盖终端侧提示、HC 授权页、状态机与信任边界说明。

v0.1 Partial impl 使用者：最终用户 + 运维 关联代码：platform/internal/harness/enrollment

版本 v0.1 · 最后更新 2026-09-15 · 对齐 docs/architecture/ARCHITECTURE.md §6.1、docs/architecture/SECURITY.md、ADR-0005、D-012/D-013/D-014。Platform 侧 Enrollment 域已实现并有契约测试；ABA 完整 Enrollment/Connector 进入 READY 仍未完成。

1. 完整流程

1
ABA 本地生成密钥
E-SIG 与 E-KEM 分开生成，私钥不出本机。Platform 不参与生成，也不接收私钥。
2
ABA 主动出站提交注册申请 + 公钥持有证明
ABA 默认无入站端口，连接由 ABA 发起。
3
Platform 返回设备码
设备码短期有效，服务端只保存哈希。终端显示，用户需要在 HC 上核对。
4
用户在 HC 待授权列表中核对设备码
列表展示设备名、平台、首次出现时间与指纹摘要。用户必须比对码，不提供「全部批准」。
5
二次确认（当前 Human Session + 二次认证）
新增 Endpoint 属于敏感操作，按 Assurance 策略要求二次 Human Auth。
6
Platform 用 ABA KEM 公钥封装并下发凭据
下发内容为该 Endpoint 的 AEC 与绑定凭据。即使设备码泄露，没有 ABA 私钥也不能解封使用。
7
ABA 校验并安全缓存，进入 READY
信任材料与证书缓存；私钥继续留在本地安全存储。

等待批准

批准后 / 被拒绝
等待在 HC 上确认… 凭据下发 .................... 已收到并解封 AEC 校验 .................... ok serial=…7c41 Trust Manifest .............. 已缓存 rev=12 状态 ........................ READY --- 另一种结局 --- 授权被拒绝或已过期。 未写入任何凭据；可重新发起注册。

终端只显示设备码与状态，不打印 Token、Ticket、证书完整值、指纹完整值或任何密钥材料。

终端显示的设备码
K7F2 · 9QDA
有效期设备码剩余 09:41。过期后需在 ABA 重新发起。

批准后 Platform 会用该设备的 KEM 公钥下发凭据。页面不显示、也不需要你抄写任何密钥。

二次确认新增 Endpoint 是敏感操作：弹出重认证，不提供「记住并跳过」。
列表层约束
  • 每台设备单独一行，没有「全部批准」。
  • 设备码必须逐字符核对，不用颜色或图标代替比对。
  • 指纹只显示截断值，完整值在设备详情内按需展开。
  • 拒绝与过期都不写入凭据，可重新发起。
  • 吊销入口与批准入口分离，避免误触。

4. 状态机

状态触发用户可见是否写入凭据
PENDINGABA 提交注册申请终端显示设备码；HC 列表出现待批准项否
APPROVED用户核对码并完成二次确认终端「凭据下发」；HC 显示已授权是（KEM 封装下发）
READYABA 解封、校验并缓存ABA 可被选择建立 Session已缓存于本地安全存储
EXPIRED设备码超期未批准终端与 HC 均提示重新发起否
DENIED用户拒绝终端提示被拒绝否
REVOKED用户或管理员吊销 Endpoint停止新连接、撤销 Token/Ticket、触发 Rekey保留历史，禁止新用

状态取值来自已接受的架构与安全契约，原型不新增状态。REVOKED 的具体清理时序与 Token/Ticket 撤销范围仍在实现中。

5. 信任边界：Platform 能看到什么

可见
  • Endpoint ID 与类型（aba / hc-web / …）
  • 申请时间与来源
  • 公钥指纹
  • 证书序列与状态、在线时间
  • 批准人与批准时间
  • 设备码哈希（不存明文）
不可见
  • E-SIG / E-KEM 私钥，以及任何端点私钥
  • Session Root Key（SRK）
  • ACP JSON-RPC 明文
  • Runtime 真实 command / args / env
  • Workspace 真实本地路径
  • Token、Ticket 明文
