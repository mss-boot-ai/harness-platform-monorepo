## 已核对的缺口

1. `SessionSetup` 只提供 Runtime ID、Workspace ID 文本输入；Gateway 只返回在线 ABA，没有本地授权项目目录。
2. 创建请求一律携带 permission/cancel，不能代表实际运行时支持。能力必须由真实执行端决定。
3. 部署环境的一次真实轮次终止事件为 provider `SERVER`、HTTP 504、重试提示 120000ms；这里只记录稳定错误元数据，不记录用户消息、上游地址或凭据。
4. DeepSeek adapter 对非 completed 结果直接退出，导致明确的模型失败被提升为 transport/UNCERTAIN；后台遗留子进程终态未及时回收。
5. HC 将所有 JSON-RPC error 轮次持久阻塞，并把 blocked/unrecoverable 对话纳入全工作区占用；部分恢复状态连关闭入口也不能使用。
6. 创建拒绝与网络中断都保留同一 unresolved creation，缺少取消/核对后脱离的完整流程；刷新会继续选择旧的失败对话。
7. `EndpointAccess.login` 总是注册新 Endpoint；同一密钥重复登录会冲突。已吊销身份没有清晰的重新登记入口。
8. 上一份 C3 报告只覆盖同一浏览器安装和确定性 ACP，不是当前部署真实模型的产品验收。

## 必须形成的用户流程

- 登录或恢复当前有效浏览器身份；已吊销的身份不能隐式恢复权限，并提供可理解的重新登记路径。
- 展示设备本地发布、当前用户有权使用的项目与 Agent 名称，选择有效组合。真实命令、参数、路径与环境留在执行端。
- 每个对话绑定执行目标；新对话能重新选择项目，切换不会丢弃其他对话的历史、草稿或已接受执行。
- 明确区分创建中、可发送、执行中、本轮失败、连接中断、结果不确定和已结束，并给出对应操作。
- 明确失败的一轮允许用户继续下一轮；连接故障按原密文核对投递；未知副作用不能自动重发。
- 失败对话可查看历史、复制草稿、核对状态、结束失效运行、归档及返回新对话。关闭操作必须重新检查服务端权限，不能依赖已坏的消息通道。
- 创建已拒绝时释放创建状态并保留草稿；创建结果不确定时使用原幂等键核对并提供明确退出流程。
- 刷新后恢复选择与草稿，但任何单对话故障都不能封锁整个导航和其他项目。
- 重命名、归档、搜索和恢复由真正的持久状态驱动；普通用户流程不要求输入底层标识。

## 当前版本设计约束

执行目录采用有界结构，只含本地允许的 ID、显示名称、允许的 Runtime 关联和必要状态。发布必须由 ABA 身份证明授权；读取必须按 owner/tenant/Endpoint scope 过滤，创建再次验证目标与本地准入。

不把模型服务 504、明确的 ACP error、进程退出和签名/密钥完整性故障合并成同一个全局失败标志。错误原因采用有界稳定分类；provider 原始异常、工具参数和响应不能进入 Platform 日志。

目录、用户动作、持久状态和测试同时变更。需要状态迁移时集中处理并写明数据影响，不静默清空原有加密数据，也不增加长期旧版回退分支。

## 验收

1. 当前版本的真实 Admin、Gateway、ABA 和 HC 上，登录、重复登录/刷新、目录选择、两项目/多对话切换均通过。
2. 确定性故障覆盖明确创建拒绝、创建响应丢失、模型明确失败、进程退出、重连、关闭、归档与草稿隔离；次数与目标项目可核对。
3. 开发部署使用真实运行时完成至少两轮对话，并验证模型失败能回到可操作状态。真实上游不可用与代码失败分别记录。
4. 目录发布越权、跨租户读取、未知项目/运行时组合、旧身份和重复操作负向测试通过。
5. 后续持久 Host、工作区互斥、多端授权、控制租约、资源和完整运行时能力仍按 `DELIVERY.md` 逐项实现与取证，不用本轮修复替代完整 Remote 的验收。
