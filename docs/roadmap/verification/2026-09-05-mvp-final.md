## 5. E2E-001：Happy Path 与关闭

内置浏览器在 `http://localhost:8001/` 创建真实 Session 并达到
`ACTIVE · HPKE KEY READY`。Session `af817e99e8…`、`809df93863…` 和后续回归均由
外部 `target/debug/test-agent` 处理，不再由 ABA 内嵌伪造响应。

Prompt `双向ACK与Journal回归-20260905-0518` 返回 Stable v1
`session/update` 与 `PromptResponse(end_turn)`；Platform 两个方向的 Frame 分别收到
Endpoint ACK，ABA Journal 出站归零。Session `d81aef8877…` 完成 Prompt 后由 HC
Endpoint DPoP API 关闭，Platform 显示 `CLOSED`；对应 `test-agent` PID 消失，ABA
与 Gateway 保持在线，Journal 当前 Session 记录被清理。

## 6. E2E-002：HC/ABA 网络恢复

HC Session `52cbd13a48…` 使用 `delay:` Test Agent：在 Agent 响应前主动关闭 HC
Socket，确认页面只有 HC 消息、ABA Journal 存在两个未确认出站包；新 Ticket/READY
后发送签名 ResumeState，Platform 重放两个内容完全相同的 EncryptedFrame。H5 解密、
去重、展示并 ACK 后 Journal 出站为 0，随后同一 Session 再次 Prompt 成功。

首次恢复暴露两个真实问题并保留修复：

1. 连续 ACK 写 SQLite 发生 `SQLITE_BUSY`，导致第二个 ACK 丢失和 HC Socket 关闭；
2. 新 WSS 连接的 HC Control Sequence 未归零，Key Package ACK 被拒绝。

修复后 16 个并发 ACK Writer 连续 10 轮通过；重放/ACK 后连接继续可用。

ABA 恢复使用 Session `f22d782f41…`：Gateway 完全停止期间 ABA 和
`test-agent` PID `1366070` 保持不变；Gateway 恢复后 ABA Generation `20 → 21`，
重发 Resume/ACK/未确认包，HC 重连后收到响应，同一 Session 的后续 Prompt 成功。
冷启动时 Gateway 暂不可用也验证了 Full-Jitter 等待与恢复。

## 8. E2E-005/006/007 与资源边界

- WSS 在每个业务包和 Pong 上复核当前 Credential；自动化测试连续 3 轮确认 HC
  Endpoint 吊销后活动 Socket 不可继续使用。Store 的吊销级联、Refresh/Ticket 拒绝和
  owner/tenant 隔离由既有测试覆盖。
- ABA Runtime/Workspace 未知 ID、相对命令、符号链接、未允许 Runtime 和远程字段均
  fail closed；外部进程使用清空后的 allowlist 环境与独立进程组。
- Journal 最大字节数、单实例租约、64 KiB ACP 消息、1 MiB Wire/密文、最多 32 ACK
  Range、256 Resume Cursor、1024 Queue 与 8 MiB 连接队列均有代码上限和负向测试。
- 16 个并发 ACK Writer × 10 轮以及 Gateway/Store Race Detector 通过。这是缩放后的
  并发烟测，不是 1,000 WSS / 100 活跃 Session 的生产容量证明。

Opaque Canary 使用了 Happy Path、网络恢复、关闭和崩溃四组唯一文本。对 Platform
SQLite 主文件/WAL、Platform 日志与 ABA Journal 扫描 exact、响应前缀和 Base64 形式，
均为零命中。Platform 数据库只保留 AAD、Ciphertext、Signature、Hash 与路由元数据；
ABA Journal 只保留摘要、状态和未确认原始加密包。

## 10. 已知限制 / 未作生产证明

- 开发 KeyStore 必须显式 `--insecure-dev-keystore` 且只允许 loopback；未验证 macOS
  Keychain、Windows CNG/DPAPI、Linux Secret Service 或 Headless KMS。
- ABA 进程内的网络重连可保留 Session Key/Agent；整个 ABA 进程崩溃后不恢复活动
  Session 明文密钥，HC 会把该 Session 标为不可恢复并要求关闭。
- Gateway Connection Directory 是单实例内存实现；未实现 Redis/NATS 跨实例 Ownership/Kick。
- 本地验证使用持久开发 Signer、HTTP/WS 与 SQLite；生产 KMS Signer、TLS/WSS、外部数据库、
  Compose/Kubernetes 和备份恢复未验证。
- 完整 1,000 idle WSS / 100 active Session、跨区域、长稳与磁盘满测试未执行。
- 固定上游 Admin Web 的 production dependency audit 尚有 1 critical / 7 high；虽然相关旧
  Node 构建依赖未进入最终浏览器 Bundle，仍需上游版本修复后才能关闭供应链门禁。
- ACP Permission Request 的完整交互 UI、Generation 2 Rekey 和多 HC Participant 不在本地
  Prompt MVP 闭环内，后续不得据此声称生产功能完整。

这些限制不影响本报告验证的本地单实例、单 HC、Prompt/Response MVP，但会阻止把当前
结果描述为生产就绪；PR 在上游依赖风险得到处置前保持 Draft。
