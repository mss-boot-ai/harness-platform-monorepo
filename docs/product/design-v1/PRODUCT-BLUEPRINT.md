## 1. 产品定义

**随时随地，把任务交给自己的 Agent。**

Harness 是面向个人与团队的跨设备 Agent 工作台。从编程和运维任务切入，让用户在自己的电脑、服务器或受控执行环境中运行兼容的 Agent，再从桌面、浏览器、手机和平板发起任务、查看进展、确认高风险操作、检查成果并继续工作。后续扩展浏览器自动化、计划任务和团队资源池，而不是首先建设一个通用 AI 聊天网站或完整 IDE。

产品价值不是暴露一个远程终端，也不是在后台展示连接协议，而是把“明确目标 → 安排执行 → 人工介入 → 获取成果 → 后续复用”变成连续体验。

### 两个面向用户的产品

| 产品 | 主要用户 | 负责什么 | 不负责什么 |
|---|---|---|---|
| Harness / HC | 执行任务的个人、团队成员、任务审批人 | 任务、对话、进度、工具授权、成果、工作区、模板、自己的设备 | 基础设施诊断、组织计费策略、默认全租户管理 |
| Harness Console / Platform | 租户管理员、运维、资源管理员、审计人员 | 组织授权、设备与资源、Agent 配置目录、任务运行元数据、策略、用量、连接器、审计 | 默认阅读 Prompt、源码、Diff 或工具参数；替用户批准具体工具动作 |

ABA 在产品中称为“设备连接器”；它仍是执行端的本地边界，不再暴露缩写给普通用户。个人用户在 HC 完成首次配对和日常操作，不必先去 Console 走完一套管理员流程。团队强制审批时，才转入 Console 待办。

## 2. 用户、场景与价值闭环

### 2.1 核心场景

1. 个人远程工作：在电脑发起修改任务，离开电脑后用手机确认一次操作，回到桌面检查 Diff。
2. 运维任务：在授权的 Linux Runner 执行诊断，查看结构化报告；有副作用的操作再次确认。
3. 团队协作：管理员分配项目与执行资源，成员在 HC 工作；授权审批人与控制权接管者不是同一角色。
4. 持续工作：把成功任务保存为模板，再建立周期计划。计划只引用审核过的模板和本地可接受配置。
5. 后续规模化：指定资源池，而非必须指定机器；系统提供排队、预算上限和可解释的资源匹配。

### 2.2 角色

个人 Owner 管自己的任务与设备。团队成员只见明确授权的项目。项目负责人管理项目成员、模板和默认配置。资源管理员管理节点和资源池。租户管理员管理组织策略和成员，但不自动获得内容解密权。审计员只读元数据。平台运营人员管理服务租户与用量，不默认进入租户内容。审批人必须另有任务级内容访问授权，不能只凭管理员身份读取具体请求。

### 2.3 成功指标（定义，不是当前统计）

北极星指标：每周被用户确认有价值的任务成果数。辅助指标：首次配对到首次成果的完成率、回访继续任务率、跨端完成一次审批的比例、模板复用率、任务终止后的可理解性反馈。不能以聊天消息数或连接数代替用户价值。产品分析不收集默认加密内容。

## 3. 领域对象：任务不是连接

```text
组织 / 个人空间
  └─ Project 产品项目
      ├─ Workspace 工作区绑定 → 某执行端的本地许可 ID
      ├─ Task 用户目标、上下文与成果集合
      │   ├─ Run 第一次或经确认的后续执行尝试
      │   │   └─ Session / Channel 协议执行与连接对象
      │   ├─ Approval 绑定某次动作的审批请求
      │   └─ Artifact Diff、报告、文件、结果引用
      ├─ Template 可复用任务模板
      ├─ Automation 模板 + 触发条件 + 执行策略
      └─ Knowledge Binding 授权知识源引用

Device / Resource Pool → Runtime Profile → Capability
Trusted HC Endpoint → 内容访问授权 + 控制租约
```

Project 不等于文件系统目录；Workspace 是对本地许可目录的稳定引用。Task ID 在跨端继续工作时保持不变；同一任务的多次执行有独立 Run ID。更换 Agent/执行环境应形成新 Run，并由用户确认上下文如何交接，不伪装成任意运行时无损迁移。重复投递协议 Frame 也不等于再次执行 Task。

产品界面使用“Agent”表达运行时选择，“模型”作为独立的能力/供应方字段。示例中出现的其他 Agent 是规划的配置项，不代表当前已集成。

## 4. 信息架构

### 4.1 HC 导航

主导航：工作台、任务、项目、模板与计划、设备、收件箱。账户区：个人/团队空间切换、可信设备、隐私、偏好、用量、帮助。

手机底部固定四项：工作台、任务、收件箱、我的。项目从工作台/任务筛选进入；模板与设备从“我的”进入，避免把六个桌面导航全部挤到手机。任务详情采用单层全屏，成果与详情按页切换。

### 4.2 Platform 导航

- 工作台：组织概览、待办。
- 资源：设备、工作区与项目授权、Agent 配置、资源池与调度。
- 治理：任务运行、成员与角色、策略。
- 运营：用量与配额、集成、审计与服务状态。

Console 首屏呈现“哪里需要处理”，而不是密文 Frame 列表。技术投递诊断放到任务运行详情的高级页签。个人版收起资源池、多租户运营等不适用功能；不是用灰色菜单塞满首屏。

## 7. 关键交互闭环

### 7.1 首次使用

登录 → 选择个人或组织空间 → 当前 HC 可信设备登记 → 安装/配对执行设备 → 选择本地已许可工作区和 Agent → 发起第一项任务。HC 展示组织要求的审批状态，个人默认不强制进入 Console。安装命令和短码仅通过实际安装器生成，原型不提供可执行的一键远程脚本。

### 7.2 创建和运行

用户输入目标并选择项目；从最近使用配置填入 Agent 与设备，明确显示选择结果。高级参数默认折叠。提交前显示工作区权限、预计用量范围（有数据时）和上限。创建后进入 Task 页面，首先确认“已接收/排队/启动中”，再显示过程。没有资源时可选择换设备或明确加入队列，不能把离线节点伪装成正在运行。

### 7.3 人工审批

执行端发起动作级 Approval，审批绑定 Task、Run、动作摘要哈希、资源范围与过期时间。HC 端解密后呈现具体内容。默认“仅此次允许”与“拒绝”；持续许可只在明确低风险、范围限定的设置页配置。过期、重复、跨 Run 或动作内容已改变的审批不得沿用原选择。组织策略是上限，不能越过本地工作区许可。

### 7.4 成果与交付

成果保留来源 Run、生成时间、文件/版本关系和用户确认。Diff、报告、图片和附件通过专门的加密制品通道规划，不把大文件塞进对话 Frame。普通确认完成不自动提交 Git、不自动发邮件、不自动发布；外部副作用要有单独明确动作。成果页面支持保存为模板和发起后续任务。

### 7.5 跨端继续

“账户登录成功”不等于“已拥有原会话密钥”。新 HC 要获得当前任务的合法内容授权和 Key Package，才能读取内容。第一版产品设计采用单控制者，多端可请求接管或以只读模式查看（按实际能力分阶段启用）；控制租约到期不自动重跑任务。手机审批不等于整个会话控制权转移。无法获取密钥时展示“需要可信设备授权”，不许管理员绕过解密边界。

### 7.6 计划与调度

计划任务由用户在可信 HC/执行端生成授权的模板、上下文和密文执行信封。Platform 只管理触发时间、候选资源范围、配额与调度元数据，不能根据明文 Prompt 自由组装任务。涉及副作用仍遵守审批策略。执行设备不可用时进入排队/跳过/提醒，默认策略必须明确。首次实现不承诺跨机器无损迁移正在执行的 Agent。

## 8. 状态与体验文案

| 维度 | 状态 | 用户看到的含义 |
|---|---|---|
| 任务 | 草稿、排队、启动中、执行中、待你确认、已完成、已停止、失败、待核实 | 描述目标执行情况 |
| 连接 | 已连接、正在重连、离线 | 描述 HC 到服务/执行端的通信，不覆盖任务状态 |
| 控制权 | 正在控制、只读、申请接管、待授权 | 描述当前设备能做什么 |
| 成果 | 生成中、可预览、待下载、不可访问 | 明确原文件可能位于哪个执行端 |

建议文案：“连接暂时中断，任务可能仍在设备上执行”；“结果尚未确认，请先检查执行记录，不会自动重新运行”；“当前设备需要授权后才能读取这项任务”；“任务已停止，已发生的外部操作不会自动撤销”。

## 9. 跨平台设计合同

Web 与桌面提供完整任务管理、并排成果和快捷键；桌面增加托盘、系统通知、本机配对入口，但不会让 HC UI 直接绕过 ABA 执行工具。macOS/Windows/Linux 使用各自系统窗口外壳，不把一个仿制标题栏强加给所有平台。

iOS/Android 使用同一套业务与视觉语义，但遵守各自安全区、返回行为、键盘、通知权限和系统分享。手机优先轻量操控；复杂代码审阅提供桌面交接。平板横屏双栏，窄屏单栏。小程序定位轻量伴随端，不假定其后台连接、加密存储、通知和文件能力等同原生应用；具体实现依据平台能力补适配，不在设计图上冒充已支持。

设计断点为产品建议：小于 600 为手机，600–1023 为紧凑/平板，1024 以上可显示侧栏，1280 以上默认三栏。仍需支持动态窗口而非只按设备型号判断。主要触控目标按 48 设计单位；正文 16 左右，信息不只靠颜色区分，键盘焦点可见，缩放后内容可重排。这些是设计目标，不是无障碍认证结论。

## 10. 视觉系统

HC 风格：温暖浅底、深墨色结构、青绿色动作色，克制的明暗对比。任务内容是主角，状态明确而不过度警报化。颜色：背景 #F6F8F5、文字 #183238、主动作 #087F72、强调浅绿 #E1F1E8、警示 #B56615。深色模式使用独立语义色，不直接反色。Platform 低保真统一灰阶，减少皮肤争论。

间距采用 4/8 基础尺度，卡片圆角 12–16，按钮 8–12；桌面正文 14–16，手机正文 16；数字等宽。组件包括 TaskCard、RunStatus、ConnectionBanner、ApprovalCard、ArtifactPanel、ResourcePicker、Composer、EmptyState、ControlLease、PrivacyLabel。所有示例任务、成员、计量与设备均为设计假数据，不代表实时业务数据。

## 11. 数据与隐私边界

默认 Opaque：任务标题、Prompt、源码、工具参数、Diff、内容摘要、模板正文、知识检索结果均留在授权 HC/ABA，或以端到端加密形式存储。Console 展示 Task/Run ID 而非从内容生成的标题。设备与项目显示名属于用户明确公开的控制面元数据，提供匿名化命名选项，避免默认上传本地目录。

Platform 可持有组织、角色、端点公钥、资源许可 ID、任务状态等必要元数据；状态来自授权执行端的最小上报。平台基础设施用量与 Agent 自报模型 token/cost 分开，后者标为估算，缺失即未知。通知默认仅说“有任务需要处理”，不推送 Prompt、工具参数或项目敏感名称到系统锁屏。日志和产品分析不得收集内容。

撤销设备只能阻止后续授权与数据访问，不能收回其已解密或复制的内容。全部密钥丢失时，平台不能凭管理员身份恢复 Opaque 内容；另行设计用户可选的加密恢复包，不能默许密钥托管。Managed 企业模式是未来独立、明确告知的产品模式，不能同时声称端到端加密。

mss-knowledge 作为知识能力提供方接入：项目配置知识源引用，ABA/授权端执行检索与上下文装配；用户知道资料会发送给哪个模型提供方。Platform 管连接器状态和授权，不自动索引会话全文。

## 12. 商业包装（方向假设，无定价承诺）

Community：自托管、个人设备、基础任务和可信端管理。Team：成员/项目授权、共享资源、组织策略、协作与计划。Enterprise：专属部署、组织身份接入、治理、审计保留与支持。Hosted Runtime 可按资源服务计量，BYOK 模型费用单独归属供应方。不能以加密或基础吊销为收费门槛，也不以未经确认的模型估价直接扣费。

当前切入市场仍是编程/运维用户；未来扩展普通用户场景需要独立场景验证，本稿不把技术控制台直接包装成大众娱乐产品。

## 13. 产品实施切片

R1 日常工作闭环：HC 工作台、任务创建/过程/成果、一次性审批、个人设备配对；Console 概览、设备、授权、任务元数据。以用户可连续完成工作为主线，不再按证书或数据库模块排产品里程碑。

R2 随身协作：手机/平板、可信端接管、收件箱、团队项目与角色、成果分享授权、模板。先实现完整 Web 响应式，再依据使用频率推进桌面和原生外壳；小程序保持清晰轻量范围。

R3 规模与持续执行：计划任务、资源池排队、预算配额、K8s 执行适配、组织运营；只在此阶段实现调度引擎，当前页面先把对象与操作设计清楚。

暂不优先：完整 IDE、任意远程 Shell、多人同时编辑同一 Prompt、默认全量服务端语义搜索、大而全的插件市场、跨机器无损迁移。
